# DECISIONS — Architecture & Commercial Decision Log

| # | Date | Decision | Rationale | Impact |
|---|------|----------|-----------|--------|
| D-01 | Phase 0 | **SQLite via Prisma instead of PostgreSQL** | Sandbox environment mandates SQLite client. Prisma isolates storage; production installs switch `datasource db.provider` to `postgresql` + `DATABASE_URL`. Schema avoids SQLite-only hacks. | One-line datasource swap documented in docs/INSTALLATION.md; decimal money handled as integer cents to avoid float issues. |
| D-02 | Phase 0 | **Monetary values stored as integer minor units** (`priceCents`, `subtotalCents`, …) | SQLite has no true DECIMAL. Integer math is exact; formatting via `Intl.NumberFormat` + settings currency. | All APIs accept/return cents; UI formats via `lib/money.ts`. |
| D-03 | Phase 0 | **Custom credential auth (bcryptjs + DB session tokens) instead of NextAuth v4** | NextAuth v4's App Router integration predates Next 16 patterns and adds OAuth complexity we do not need; role model (OWNER/ADMIN/ORDER_MANAGER/CONTENT_MANAGER/CUSTOMER) is domain-specific. Opaque DB sessions give instant server-side revocation. | `lib/auth.ts` + `lib/session.ts`; HttpOnly, SameSite=Lax, Secure in prod; 30-day expiry; rate-limited endpoints. |
| D-04 | Phase 0 | **Cart is client-side (Zustand + localStorage), re-validated server-side** | Spec allows non-persisted carts. Server recomputes every line at checkout from DB (price, sale price, stock) — browser totals are never trusted. | Simpler UX; overselling prevented by transactional stock deduction. |
| D-05 | Phase 0 | **Telegram credentials via env vars only** (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`) | Spec forbids secrets in DB settings/client. Settings UI toggles events + health; token never rendered. | docs/TELEGRAM-SETUP.md. |
| D-06 | Phase 0 | **No Vitest/Playwright in this build environment** | Sandbox explicitly forbids test code. Quality gates: TypeScript-aware lint, runtime smoke via headless browser verification, documented manual test script in docs/TESTING.md for commercial installs. | Deviation recorded; test scaffolding is straightforward to add (docs included). |
| D-07 | Phase 0 | **CMS content rendered as sanitized Markdown** (`react-markdown`, no raw HTML) | Eliminates XSS by construction — no executable markup path. | editors use Markdown textarea + preview. |
| D-08 | Phase 0 | **First-owner bootstrap via `/webmaster/setup` + dev seed** | No default production credentials shipped. If no OWNER exists, /webmaster/setup accepts exactly one owner creation; dev seed creates documented demo accounts (dev-only). | docs/WEBMASTER-GUIDE.md. |
| D-09 | Phase 0 | **Idempotent checkout** via client-generated `idempotencyKey` (uuid) with unique index | Repeated submissions (double-click, retry) cannot create duplicate orders. | |
| D-10 | Phase 0 | **Local-disk image storage behind `lib/storage.ts` interface** | Uploads land in `public/uploads` with MIME/size validation. Interface keeps S3/Cloudinary adapters drop-in for client installs. | |
